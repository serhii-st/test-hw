# Change Review Checklist

Answer every item with **Yes**, **No**, or **Not applicable**, and give evidence:
a link, command output, or file reference. An item without evidence counts as No.
Any No blocks merge unless a human records an exception below.

| # | Question | Answer | Evidence |
|---|----------|--------|----------|
| 1 | Is an approved specification linked? | | |
| 2 | Is the change within scope? | | |
| 3 | Are acceptance criteria covered by tests? | | |
| 4 | Did validation pass? | | |
| 5 | Are secrets absent? | | |
| 6 | Are dependencies justified? | | |
| 7 | Are protected paths unchanged or approved? | | |
| 8 | Are relevant documents updated? | | |

Item 7: if a protected path changed, the evidence must list each path plus the name of an
approved reviewer from [AGENTS.md](../AGENTS.md#approved-human-reviewers) and the approval date.
